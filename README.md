# Finding Ledger

Finding Ledger 是面向长期 Agent 工程任务的**证据化发现账本**：保存调试、实验和代码审查过程中形成的结论，让后续会话能够检索、验证、纠正并复用它们。

它解决的核心问题是：上下文压缩或会话切换后，Agent 忘记已经完成的排查；未经验证的假设被当作事实；旧结论在环境变化后仍被错误复用。

## 核心设计原则

1. **结论与证据分离。** 一条结论可以关联多个支持、反驳或补充证据；同一来源也可被多个结论复用。
2. **状态维度正交。** “结论是否有证据支持”与“记录是否仍为当前版本”是不同问题。
3. **按条件复用。** 项目、代码版本、运行环境和任务范围决定旧结论能否直接适用。
4. **保留纠错历史。** 反证、取代和撤回都应留下可追溯记录，不通过静默覆盖抹去历史。
5. **按需注入。** 注入的是与当前任务相关、适用范围明确的最小结论集，而不是整本账本。
6. **可追溯优先于伪精确。** 第一版不依赖未经校准的数值置信度；优先保存来源、条件和状态变化理由。

## 与其他项目记忆的分工

- **timeline.md / 工作日志：** 记录事件顺序与工作归因。

- **项目文档：** 解释系统设计、接口和使用方式。
- **Finding Ledger：** 保存从实际工作中得到的结论、证据、适用条件以及结论如何被修正。

## 当前范围

第一阶段聚焦单机 SQLite、结构化检索和宿主会话集成。语义向量检索、自动判断结论失效、跨项目知识共享和复杂证据评分均不作为起步依赖。详细决策与验收标准见[设计文档](docs/README.md)。
